# Coding standards

The rules `code-review` enforces on a diff, alongside `AGENTS.md`. Where this
file and the code disagree, the code is wrong — except for decisions recorded in
`docs/adr/`, which override both.

## Language and voice

1. **English only.** Code, identifiers, comments, docstrings, UI strings, commit
   messages, issue text. A French string in a public repo is a bug.
2. **Comments explain why, not what.** A comment restating the code is noise.
   A comment naming the paper behind a formula, or the quirk a branch works
   around, is required.

## Dependencies

3. **Runtime dependencies stay at `fastapi` + `uvicorn`.** Anything else must be
   standard library. See ADR-0003.
4. **Dev-only tooling goes in `requirements-dev.txt`** (`pytest`, `ruff`). It
   must never be imported by `app/`.

## Configuration

5. **No magic numbers in logic.** A tunable threshold, weight, distance or
   duration belongs in `app/config.py` with a comment naming its source or
   meaning. Constants that are structurally fixed (earth radius, unit
   conversions) may stay local if documented.

## Python style

6. **Type hints on every public function and method signature.** Private helpers
   are encouraged to have them but not required. `from __future__ import
   annotations` at the top of new modules.
7. **Docstrings on every module and every public function.** One line is enough
   for the obvious ones. Formula-bearing functions must name the model and its
   source (Daniels, Banenberg, Riegel, Gabbett, Seiler, Foster).
8. **88 columns.** `ruff format` and `ruff check` are the arbiters; do not argue
   with the formatter in review.
9. **`except:` and `except Exception:` are banned** unless the handler logs and
   re-raises or converts to a documented fallback. A malformed input file must
   be **skipped with a logged reason**, never crash the scan and never be
   silently swallowed.
10. **Pure functions first.** Analytics live in `analysis.py` / `coaching.py`
    and take data in, return data out — no I/O, no globals, no clock reads except
    where a function is explicitly about "now". This is what makes them testable.

## Tests

11. **Anything formula-bearing ships with a test.** Training load, CTL/ATL/TSB,
    ACWR, zone bucketing, GAP correction, VDOT, Riegel, plan progression,
    parser output. A new branch in a formula without a test is a review blocker.
12. **Test behaviour at seams, not internals.** Preferred seams: public
    functions in `analysis.py` / `coaching.py`, parsers through `parse_file()`,
    persistence through `Store`. No test may import a private helper it does not
    own the behaviour of, and no test may reach into SQLite directly.
13. **Never commit real activity data.** Fixtures are synthetic, generated by a
    script under `tests/fixtures/`. No personal GPS, no real dates of birth.
14. **Literature beats implementation.** When a test derived from a published
    model contradicts the code, the test wins — but the fix is a separate commit
    with the before/after numbers shown, never a silent edit buried in a feature.

## Frontend

15. **No framework, no build step, no transpiler.** Plain `.js` and `.css`
    served as-is, vendored libraries only (Leaflet, Leaflet.heat).
16. **No inline event handlers** (`onclick="..."`). Wire listeners in `app.js`.
17. **User-visible text is data-driven where it repeats.** Metric explanations
    reuse the glossary vocabulary; do not re-word a definition per screen.

## Accessibility (WCAG 2.1 AA minimum)

18. Every interactive control is reachable and operable by keyboard, with a
    visible focus indicator.
19. Every input has a programmatic label. Every icon-only button has an
    accessible name.
20. No meaning conveyed by colour alone: zones, bands and risks carry text or a
    pattern in addition to colour.
21. Charts provide a text or table alternative for the data they encode.
22. Contrast ratio at least 4.5:1 for body text, 3:1 for large text and UI
    boundaries.

## Privacy

23. **No telemetry, no analytics, no phone-home.** The only outbound requests are
    map tiles and the opt-in LLM coach.
24. **Secrets come from environment variables.** Never log a key, never write one
    to the database, never send one to the browser.

## Commits

25. **Conventional Commits.** `feat:`, `fix:`, `refactor:`, `test:`, `docs:`,
    `chore:`, `perf:`, `a11y:`.
26. **Scopes**: `api`, `analysis`, `coaching`, `store`, `parsers`, `connectors`,
    `ui`, `a11y`, `docs`, `tests`, `deps`, `build`. Example:
    `feat(coaching): add session-RPE load source`.
27. The body explains **why** and states any behaviour change. A formula change
    must include the before/after value on a real example.

## Review checklist

A diff is ready when every line below is true.

- [ ] English only, no leftover debug output or commented-out code
- [ ] No new runtime dependency; dev tooling not imported by `app/`
- [ ] New tunable values live in `app/config.py`
- [ ] Public functions typed and documented
- [ ] Formula-bearing change covered by a test that fails without it
- [ ] Parser change tested against a synthetic fixture, not personal data
- [ ] Accessibility rules 18–22 verified for any UI change
- [ ] `ruff check` and `ruff format --check` clean
- [ ] `python -m pytest` green
